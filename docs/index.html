Native audio architecture

Voice, all the way down.

No speech-to-text deconstruction when the model supports native audio. PCM goes into the multimodal projector; text and speech come back from the same generation loop.

OffconAI treats native voice as a runtime capability, not a visual wrapper. Models without it are labeled honestly and can still use the separate local speech pipeline.

  • Input16 kHz mono PCM, buffered for an explicit conversation turn.
  • Output24 kHz PCM from the native audio helper, synchronized with streamed text.
  • SessionTap to record one buffered turn, tap to submit. Cancellation and clean teardown are explicit; continuous duplex input remains a future target.

FAQ

Questions, answered.

Does OffconAI work offline?

Yes. After a model is downloaded, inference, chat history, document RAG and the local API run on-device. Network access is only used when you explicitly download a model, connect an MCP server, or expose the optional LAN API.

Can I run my own GGUF models?

Yes. OffconAI runs GGUF models through llama.cpp and LiteRT-LM bundles, including vision projectors and native Omni audio where the model and runtime support them.

Is this a private alternative to cloud AI?

It is a local-first alternative for offline work: no account, no telemetry, and no prompts sent to a hosted model. Answer quality depends on the model you run and the memory of your device.

Does it collect telemetry?

No analytics or telemetry are built in. Conversations and credentials are stored locally, and the chat database is encrypted with Android Keystore AES-256-GCM.
